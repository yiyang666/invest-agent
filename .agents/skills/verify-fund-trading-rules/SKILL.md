# 基金交易规则核验

把爱基金渠道的当轮只读预检作为动态交易规则的第一事实源。只核验规则，不生成投资信号，不提交交易。

## 强制准备

1. 先阅读项目 `AGENTS.md`、`config/investment_policy.yaml` 和 `docs/integrations/thsfund-review.md`。
2. 完整阅读相邻 `../thsfund/SKILL.md`，执行其 SDK 自检。
3. 查询申购规则时完整阅读 `../thsfund/references/purchase/purchase.md`；查询赎回规则时完整阅读 `../thsfund/references/redeem/redeem.md`。
4. 阅读 [references/source-contract.md](references/source-contract.md)，按其中字段和降级规则执行。

## 意图路由

- 可购状态、暂停、限额、起购/追加金额、申购费或持续费用：使用只读 `aijijin fund subscribe-init` 与 `aijijin fund fee-rule`。
- 当前持仓的赎回费、持有批次、可赎份额、最低剩余份额或到账时间：使用只读 `aijijin holding list` 定位精确账户，再调用 `aijijin fund redeem-render`。
- 同时询问申购和赎回：分别运行两条只读流程，标明各自核验时点。
- 历史某日规则：当前 CLI 不能证明历史事实；只可读取本地已版本化规则。缺失时明确为未知，不搜索合同、招募说明书或网页补证。

## 执行约束

1. 锁定用户指定的基金代码；接口失败时不得自动替换基金或账户。
2. 只调用查询、初始化、费用或渲染命令。禁止调用 `fund buy`、`fund redeem`、`trade revoke`，也不得用提交后撤单来探测规则。
3. 不调用或展示 Work Token、Refresh Token；不使用 `curl` 或 Python SDK 绕过 `aijijin` CLI。
4. 不持久化 CLI 原始响应。原始响应可能含完整账户、客户号和交易账号；只保留脱敏归一化事实。
5. 费率、限额和状态必须带渠道与核验时间。当前结果不得冒充历史长期规则。
6. 网络、5xx、认证或响应异常时不循环重试；按 `thsfund` 错误路由处理。
7. CLI 已给出规则时不得搜索网页、合同或招募说明书“确认一下”；CLI 缺失、冲突或历史规则一律标为未知或仅限本地既有版本化事实。

## 输出要求

先给结论，再给证据边界。至少包含：

- 基金代码与名称；
- 爱基金渠道当前状态和核验时点；
- 用户所问的限额、费率、份额或到账规则；
- 数据来自哪个 CLI 只读命令；
- 未提交任何申购、赎回或撤单；
- 缺失、冲突或仅能估算的字段。

若根据持有批次估算赎回费，明确写出适用持有天数、费率、净值日期和“最终以基金公司确认结果为准”。不要展示完整银行卡号、交易账号、客户号或底层状态码。

## 与其他能力的边界

- 需要真实持仓或交易查询时，继续遵循 `thsfund` Skill。
- 需要把规则写入本地研究仓或批量更新基金池时，配合 `fund-data-collect`，但远端响应必须先脱敏、校验和版本化。
- 需要真实买入、赎回或撤单时，本 Skill 到此结束，重新进入 `thsfund` 对应交易流程并取得逐笔精确确认。
