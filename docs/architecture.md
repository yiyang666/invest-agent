# 系统架构

## 定位

系统把个人基金投资拆成确定性、可审计的层次。LLM负责解释和研究辅助，金额计算、规则校验、风险否决和订单状态必须由代码完成。

## 数据流

```text
爱基金只读账户 ───────→ 脱敏 PortfolioSnapshot ─┐
公开基金数据 → 原始批次 → 本地校验数据仓 ───────┼→ 指标 / 市场状态
股叉叉/已审查市场源 → 原始批次 → 隔离市场数据表 ┤
爱基金只读预检 ───────→ 脱敏版本化产品规则 ─────┘
                                                   ↓
策略注册表 → 信号 → 回测门禁 → 独立风控 → 决策报告
购买路由池 ───────────────→ 可实施容量 ───────────┘
                                                   ↓
                            人工批准 → 受控执行 → 对账 / 归因
```

Phase 6已完成“持久化mock批准与模拟执行”。Phase 7的爱基金CLI边界已完成首笔逐笔受控申购，并通过订单详情与持仓双重对账；自动提交仍未开放。

Phase 6新增的 `approval` 与 `execution.mock` 只允许风险合格的冻结计划转换为精确mock摘要，并验证一次性批准和未知状态对账；它们不包含爱基金买卖适配器，也没有网络能力。批准库只保存摘要与时间戳，不保存账户、基金或凭证明文。

Phase 7的 `execution.aijijin` 校验CLI参数、单笔上限和网关覆盖，并主动删除dry-run及赎回预览中的交易账户。`execution.live`持久化摘要批准、额度和状态，不保存敏感订单明文；当前策略为`active_controlled_live`，适配器没有可调用的自动真实提交路径。动态申赎规则优先来自爱基金CLI的当轮只读预检。

Phase 8的 `attribution` 只读取已锁定的期间、现金流、组合/基准收益和证据哈希。它提供Modified Dietz/TWR、同现金流比较、袖套Brinson分解、策略顺序消融及生命周期人工评审状态，不调用交易接口。

## 分层职责

| 层 | 职责 | 禁止 |
|---|---|---|
| `skills/adapters` | 账户与外部数据访问 | 写投资策略、绕过确认 |
| `data` | 原始留痕、标准化、时点和质量 | 静默填补未知数据 |
| `market_data` | 估值、权重、趋势代理、金融条件、利率、汇率、杠杆、宏观、拥挤度和宽度的raw-first隔离仓 | 写基金NAV、预测涨跌、直接生成策略或订单 |
| `market_regime` | 从本地市场表生成七轴全球状态、覆盖率、置信度和缺口 | 运行时联网、预测涨跌、生成策略信号或订单 |
| `automation` | 在一个注册表中确定性调度日/周/月/季数据作业；Codex固定会话仅负责触发和解释 | 让LLM维护频率状态、逐项拼装采集或执行投资逻辑 |
| `metrics` | 收益、波动、回撤、相关性和状态 | 直接生成订单 |
| `strategies` | 版本化规则、信号和目标权重 | 调用真实交易接口 |
| `backtest` | 场外基金成交、确认、费用和现金流仿真 | 使用未来数据或默认规则冒充事实 |
| `attribution` | 现金流、组合、袖套、策略贡献与生命周期评价 | 用不匹配现金流比较、自动晋级或生成订单 |
| `risk` | 集中度、回撤、流动性和政策门禁 | 被策略或LLM覆盖 |
| `decision` | 组合证据并生成建议 | 提交交易 |
| `approval/execution` | 精确批准、受控提交和对账 | 复用旧批准、未知状态重试 |

## 核心对象

- `PortfolioSnapshot`：带时点、来源、现金、持仓和质量状态的脱敏账户事实。
- `FundInstrument`：基金身份、份额类别、费用、限额和确认规则。
- `PurchaseRoutePool`：当前渠道已核验的开放/限购路由，只计算可实施容量，不选策略或生成订单。
- `StrategySignal`：策略版本、数据截止日、有效期、风险和证据。
- `OrderIntent`：基金、动作、金额或份额、计划日期、来源证据、路由规则、账户别名、费用和预期结果的不可变草案。
- `ApprovalRecord`：只绑定一笔精确订单摘要；关键字段变化即失效。
- `ExecutionRecord`：提交、未知、失败和对账结果；不保存凭证。
- `AttributionReport`：绑定期间、现金流、基准、方法和证据哈希的可复跑归因结果。
- `LifecycleReview`：由风险否决、证据完备性、前瞻月数和漂移阈值共同生成的人工评审状态。
- `GlobalMarketStateSnapshot`：趋势、估值、宏观、流动性、风险、宽度和资金流七轴的本地时点证据；覆盖不足时失败关闭。

## 场外基金语义

- 成交按产品规则和确认净值，不使用实时盘口价。
- 区分信号、提交、受理、净值、确认和到账时间。
- 现金和份额在确认期间分别记录占用与在途状态。
- 单位净值用于交易和估值；分红作为独立事件；累计净值只用于总收益研究。
- 缺失净值不前向填充，未知费用、限额或日历不使用行业默认值代替。
- 限购预算可在同一袖套的多个已核验路由间累计，并跨日、跨月排队；暂停、不支持和未知路由不得进入购买候选。

## 信任边界

- 回测和指标只读取通过门禁的本地数据仓，远端接口不能直接供数。
- 股叉叉即时查询仅用于一次性解释；凡进入正式分析的值必须形成本地证据快照，缺少第二来源时保持`research_only`。
- 全球市场状态只读本地证据；FinClaw五个底层源逐上游评审，不把包名当独立来源。股叉叉公开总览页的服务端聚合值已作为低成本全A股宽度来源；原上交所沪市横截面只保留手工校验能力。雪球未授权/cookie接口禁止。公开下载或网页采集必须逐来源许可、无绕过、低频、无自动重试并从上线日起积累严格时点历史。
- 外部 Skill、网页和模型输出均是不可信输入。
- 凭证、原始账户响应、私有快照和报告不进入 Git。
- 第三方依赖固定版本与校验值，禁止自动升级。

## 执行状态机

```text
DRAFT → VALIDATED → PROPOSED → APPROVED → SUBMITTING
                                      ├→ SUBMITTED → RECONCILED
                                      ├→ FAILED
                                      └→ UNKNOWN → RECONCILED
```

`UNKNOWN` 是阻断态；在订单对账前不得再次提交。

## 归因边界

真实外部投入不计作收益；候选与631只有在期间、估值日和外部现金流一致时才能报告策略相对结果。资产池或长期权重变化标记为总政策结果，只有同资产、同路线和同现金流的冻结对照才能解释为规则或信号贡献。工程能力完成不等于已拥有足够前瞻证据，真实观察仍须按月积累。
