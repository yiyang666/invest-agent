# ADR-0034 本机只读投资工作台与持仓日快照

日期：2026-10-09；状态：接受。

## 决策

用户选择先做本机 Web，直接读取本地 SQLite。采用 Python 标准库 HTTP 服务与无构建静态页面，不增加框架依赖。只监听 127.0.0.1，限定 Host / Origin 和静态文件白名单；所有 Web 数据库连接使用 mode=ro 和 query_only。无交易、写入、远程采集或模型调用接口。

净值只展示通过质量门禁的本地批次。基金分类拆成两个正交维度：基金类型描述实际标的或管理方式（例如标普500、纳斯达克100、日本主动增强），仓位归属描述其在本组合中的核心仓、防御仓或卫星仓角色。分类、基金池、策略规则仍读取既有版本化配置；不复制第二套策略逻辑。完整规格留在详情中，概览展示基准和研究状态。没有明确实盘执行记录时展示“未登记实盘执行策略”。

“监控基金”是基金级事实入口，集中展示双分类、净值日期、最近采集、质量门禁和新鲜度；“数据更新”只展示维护作业和运行记录，避免同一份基金状态在两个页面重复出现。

持仓通过受审查 aijijin 0.2.1 的 holding overview 读取，原始响应只留内存。通过白名单、有限数值、代码唯一性和总额对账后，追加写入 SQLite portfolio_snapshots，保留原有私有 JSON 快照供既有模块使用。内容哈希去重，不覆盖历史。同日多份快照，Web 展示最后一份，数据库仍完整保留。

## 日期语义

as_of 是实际采集时间，nav_date 和 income_date 仅使用渠道明确提供的字段，缺失则显示未提供。不能根据采集日期自行推断上一交易日，更不能把账户资产变化当作投资收益。QDII、节假日或渠道分批更新时允许日期不同。页面区分采集完成和净值日期新鲜度，5 个自然日阈值沿用现有采集配置，不宣称阈值内就是今日数据。

## 调度

在现有 maintenance_cli 中新增 portfolio_daily，排列在 fund_data_daily 前，便于基金集合包含新增持仓。沿用工作日晚间总控、进程锁和周期去重。持仓失败不阻断其他独立作业；维护日志只记录发布状态，不复制账户数据。既有自动化提示词同步更新，只开放该只读作业。

## 边界与后续

不部署公开站点、不上传数据库。Sites 云端托管不能直接读取个人电脑 SQLite；未来若需云端查看，需要单独设计访问控制和脱敏同步。首版不建立新的实盘执行状态机、在线编辑分类或在线调整策略。此工作台是现有研究系统的可视化入口。
