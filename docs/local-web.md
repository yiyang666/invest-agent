# 本机投资工作台

macOS 可双击仓库根目录的 `启动投资看板.command`，它会启动服务并打开浏览器。保持弹出的终端窗口运行即可。

也可在仓库根目录运行：

```sh
scripts/run_local_web.sh
```

打开 http://127.0.0.1:8765 。终端保持运行，Ctrl+C 停止；端口冲突可加 `--port 8766`。使用项目现有 `.conda-env`，无新增依赖。Web 只监听本机，不能从其他设备直接访问。

页面包括投资总览（最新基金收益、持仓分布与宏观市场）、监控基金（搜索、双分类、净值与采集质量、可切换区间的业绩走势，以及独立的13期RSI净值波动图）、每日持仓（日期选择、金额隐藏）、策略库（登记与历史版本、规则详情、明确绑定的本地回测摘要）、数据更新（维护作业状态与运行记录）。业绩走势支持近1月、3月、6月、1年、3年和全部，并按显示区间首尾累计净值计算收益率；选择近3年但历史不足时自动展示全部历史并给出短暂提示。RSI对最近13个累计净值变化采用简单上涨/下跌幅度汇总，已用多只基金的同花顺同日值核对；页面区间按钮只裁剪展示。30/70色带表达近期涨跌力量，不等同于跟踪指数PE TTM五年估值分位，也不直接生成交易建议。

“接口配置”是首次部署和后续更换令牌的配置入口，可保存股叉叉和金十 MCP 令牌。令牌从浏览器直接提交给当前本机服务，通过 macOS `security` 的标准输入写入登录钥匙串，不出现在进程参数中；页面只显示“已配置/未配置/需要解锁或授权”，不会回显明文。保存后输入框立即清空。页面关闭后配置仍然有效，日常维护、定时任务和数据 CLI 继续沿用原有的“进程环境变量优先、缺失时读取钥匙串”流程，不依赖网页运行。无论网页在本机直接打开还是通过 SSH 端口转发访问，这一存储路径都相同。

宏观市场展示允许列表内的沪深300、恒生、标普500、富时100、德国DAX和日经225。报价来自金十接口，必须先归档、校验并发布到本地市场数据表；涨跌点数由点位与涨跌幅反算。点击“更新市场”只运行这一条已审查的报价采集，不查询账户、不运行策略，也不生成订单；采集失败时继续显示上一次通过门禁的本地值。上证指数、创业板指、科创50和纳斯达克当前没有已审查的正式报价源，因此不以未审查接口或基金代理冒充实时指数。页面同时提供股叉叉与雪球行情的外部跳转，二者不会被网页自动抓取。

手工更新需要启动 Web 的进程环境包含 `JIN10_MCP_TOKEN`，或在“接口配置”中保存金十令牌。登录钥匙串锁定或当前会话不允许钥匙串交互时，页面会展示本机和 SSH 场景下的解锁步骤。可以在部署项目的 Mac 上打开“钥匙串访问”并解锁“登录”钥匙串，或在交互式终端运行 `security unlock-keychain ~/Library/Keychains/login.keychain-db` 后按提示输入系统登录密码；密码不得写进命令或网页。缺少凭证时继续使用上次数据，不会降级写入明文文件。

页面首次打开时读取一次完整本地视图；此后每 10 分钟只检查 SQLite、配置、策略、回测和维护记录的轻量版本，版本未变化时不查询或重建完整视图。页面从后台恢复可见时也遵循同一检查间隔。版本变化后自动加载新数据；基金净值详情按数据版本缓存在浏览器内。右上角“刷新”会立即重建本地视图，但不触发账户查询或远程采集。

## 数据来源

- 净值、持仓与已发布市场报价：`data/private/invest_agent.sqlite3`。所有视图查询均为只读；只有“更新市场”可以通过固定脚本追加一批允许列表内的金十报价。
- 分类与监控集合：`config/fund_watch_catalog_v1.json` 提供稳定的监控分类，研究池、购买路由池和已登记月度持仓分类可提供更具体的既有分类；未登记的基金显示“待分类”。
- 策略：`strategies/registry.json` 与 `strategies/specs/`，检验登记证据，不把研究状态当成实盘执行。
- 更新记录：统一维护任务私有状态与报告。

持仓展示采集时刻的渠道快照。渠道给出净值日期、收益日期时分别展示，否则显示“未提供”，不会自动标成上一交易日。钱包或基金分类采集不完整时提示部分数据。除用户点击“更新市场”外，浏览页面不调用外部数据源或模型；网页没有交易接口。

总览基金收益只汇总最新渠道快照中各持仓的 `latest_income`，钱包资产始终排除。渠道没有提供统一收益日期时如实提示，不根据资产差额自行推算。

## 日常维护

晚间总控在同一固定会话分两次触发：22:35 运行 22:30 到期的 `portfolio_daily` 只读持仓快照，23:35 再运行 23:30 到期的基金净值和市场数据。两次仍共用统一CLI、状态、锁和运行记录。手工运行也应使用统一入口：

```sh
scripts/run_data_maintenance_cli.sh plan
scripts/run_data_maintenance_cli.sh run-job --job-id portfolio_daily
```

旧的脱敏持仓 JSON 可一次性导入（失败门禁记录自动拒绝）：

```sh
.conda-env/bin/python -c 'from pathlib import Path; from invest_agent.data.portfolio_store import import_snapshots; print(import_snapshots(Path("data/private/invest_agent.sqlite3"),Path("data/private/portfolio_snapshots")))'
```

Web 不负责调度唤醒；晚间任务仍依赖现有 Codex 自动化运行环境和 CLI 登录状态。登录失效或采集失败会保留历史快照并显示更新作业失败。测试用例只使用临时合成数据，不把个人持仓提交到 Git。
